# NOVA Decks OS — Implementation Plan

## Stack
- **One deployable app:** Next.js 16 (App Router, React 19, server actions + route handlers), TypeScript.
- **Database:** PostgreSQL. Drizzle ORM schema in `src/db/schema.ts`; SQL migrations in `drizzle/` generated by drizzle-kit and applied by `npm run db:migrate`.
- **Auth:** Better Auth (email + password, database sessions, httpOnly cookies). Public sign-up is off unless `ALLOW_SIGNUP=true`.
- **Tests:** Vitest against a real PostgreSQL (embedded locally, service container in CI).

## Module layout
| Module | Path | Owns |
| --- | --- | --- |
| core | `src/modules/core` | Request/company context, roles & permissions, errors |
| crm | `src/modules/crm` | Customers, contacts, addresses, opportunities, stages, tasks, activity timeline, job conversion, exports |
| design | `src/modules/design` | Deck design model (pure), validation, geometry; persisted designs |
| estimating | `src/modules/estimating` | Catalog + company pricing, takeoff calculation (pure), estimates & immutable revisions, CSV |

The deck model is one pure TypeScript object (`DeckDesignModel`). The plan view, 3D preview, takeoff, perimeter and CSV all read from `analyzeDeck(model, product)` so they cannot disagree.

## Tenancy
- `companies` → `memberships(company_id, user_id, role)` → Better Auth `user`.
- Every tenant table has `company_id NOT NULL`. Child rows use **composite foreign keys** `(company_id, parent_id)` so the database itself rejects a row linking to another company's record (e.g. an opportunity cannot point at another company's customer, an assignee must be a member of the same company).
- The active company comes from the URL slug (`/c/{slug}/...`) and is **resolved server-side to a membership** for the signed-in user on every request. No company id is ever accepted from the client. Every service function takes that context and filters by `ctx.companyId`, including lookups by id; misses return 404 (no existence leak).

## Milestone 1 scope (this branch)
1. Workspaces, memberships, Owner/Admin vs Team Member permissions (server-enforced), seeded NOVA + a second fictional contractor.
2. CRM: customers/contacts/addresses, opportunities with stage/service/source/assignee/follow-up, search & filters (stage, assignee, overdue), tasks, chronological activity with actor, idempotent won→job conversion.
3. Deck designer: rectangular attached deck + one straight stair on the outer edge; ft/in inputs; SVG dimensioned plan; three.js 3D preview; board takeoff; open perimeter; validation; CSV export.
4. Estimates: draft estimate revisions that snapshot design + product + price so later changes never alter saved revisions.
5. Hosting readiness: env config, `.env.example`, CI (lint, typecheck, test, build), deployment notes.

## Out of scope / future
Scheduling, change orders, live supplier feeds, customer portal, accounting (QuickBooks) and JobTread integration, structural sizing, permit drawings, waste/cut optimisation, add-ons (fascia, railing, fasteners), invitations/email, Postgres row-level security as defense-in-depth.
